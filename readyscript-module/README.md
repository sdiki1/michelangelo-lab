# Модуль `michelangelo` для ReadyScript

Связывает коробочную витрину `https://michelangelo-lab.ru` с админ-панелью
`https://admin.michelangelo-lab.ru`.

## Что делает

1. **Узнаёт покупателя в миниаппе.** JS определяет Telegram/MAX, забирает
   `initData` и кладёт личность в сессию.
2. **Штампует заказ.** При оформлении заказ получает поля `ml_platform`,
   `ml_platform_user_id`, `ml_init_data`.
3. **Шлёт вебхуки.** Создание и любое изменение заказа уходит в админ-панель
   через очередь с повторами.
4. **Собирает действия на витрине.** Просмотры страниц и товаров, добавления в
   корзину — пачками, фоном.
5. **Позволяет привязать вручную.** Поля `ml_platform` и `ml_platform_user_id`
   редактируются прямо в карточке заказа; после сохранения привязка уезжает в
   админ-панель.

## Установка

1. Скопировать каталог в коробку:

   ```bash
   scp -r michelangelo/ user@michelangelo-lab.ru:/path/to/site/modules/
   ```

2. В админке ReadyScript: **Модули → Установить** → `michelangelo`.
   Установщик создаст таблицу `michelangelo_outbox` и сгенерирует секрет.

3. **Модули → Michelangelo → Настройки**:

   | Поле | Значение |
   |---|---|
   | Адрес админ-панели | `https://admin.michelangelo-lab.ru` |
   | Общий секрет подписи | скопировать в `.env` админ-панели |
   | Собирать действия на витрине | да |
   | Собирать действия только в миниаппе | да |

4. В `.env` админ-панели прописать тот же секрет и перезапустить:

   ```bash
   RS_MODULE_SECRET=<секрет из настроек модуля>
   docker compose up -d --build admin
   ```

5. Включить cron ReadyScript (досылает накопившуюся очередь):

   ```
   */5 * * * * php /path/to/site/cron.php
   ```

## Проверка

```bash
# Из консоли коробки: подпись должна совпасть с той, что ждёт админ-панель
php -r 'require "modules/michelangelo/model/api.inc.php";
echo \Michelangelo\Model\Api::sign("test-secret", 1700000000, "{\"a\":1}"), "\n";'
# → sha256=8cb2c3355fca388e9ac2caec004f4d5d7045d74937ab5faad61dc11682247a9f
```

Тот же вектор закреплён тестом `tests/test_webhook_security.py` в админ-панели:
если значения разошлись, вебхуки будут отбиваться с 401.

Дальше — открыть витрину в миниаппе и посмотреть раздел **Витрина** в
админ-панели: там должны появиться `page_view`.

## Что нужно проверить на вашей инсталляции

Модуль написан по документации разработчика ReadyScript 6.x, но часть API я не
мог проверить без доступа к вашей коробке. Перед боевым запуском стоит убедиться:

- **Имена полей заказа.** `Handlers::buildOrderPayload()` перебирает известные
  варианты (`totalcost` / `total_cost` / `total`), но если у вас редакция с
  другими именами — поправьте список в `Handlers::field()`.
- **Сигнатура `\RS\Router\Route`.** Порядок аргументов конструктора роутов между
  версиями RS менялся; если `/michelangelo/track/` отдаёт 404, поправьте
  `Handlers::getRoute()`.
- **Форма события `ormAfterWriteShopOrder`.** Обработчик принимает и объект
  заказа, и массив параметров (`Handlers::extractOrder()`), но если у вас
  событие отдаёт что-то третье — добавьте разбор туда же.
- **Подключение JS.** `$app->addJs('%michelangelo%/miniapp.js')` использует
  алиас модуля; если скрипт не подключился, укажите путь целиком.

Если модуль установился, а вебхуки не идут — смотрите таблицу
`michelangelo_outbox`: в `last_error` лежит ответ админ-панели.

## Селекторы для сбора действий

По умолчанию JS ловит клики по `.add-to-cart` и ссылкам на корзину. Чтобы
разметить свои элементы, добавьте атрибут:

```html
<button data-ml-action="checkout_start">Оформить</button>
```

Или вызовите из шаблона напрямую:

```js
michelangelo.track('promo_click', { product_id: '123' });
```
